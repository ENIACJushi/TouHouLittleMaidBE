
### 皮肤包支持动画和语音

开始时间：2026/05/31

#### 新版本问题解决

> 此任务因缺少排查方向暂时搁置

首先要解决的是新版本（1.26.20+）的一个问题：使用附加皮肤包后，进入世界的加载会变得很慢。

原因尚不明确，或许要先去 [BUG 反馈网站](https://bugs.mojang.com/browse/MCPE)  搜索一下。

以及一些文档，检查最近的变化：
- [更新日志原文](https://www.minecraft.net/en-us/article?filter=%7B%22news%22%3A%7B%22news%22%3A%7B%7D%2C%22subscription%22%3A%7B%22Minecraft%3A+Bedrock%22%3Atrue%7D%7D%7D)
- [更新日志翻译](https://klpbbs.com/forum-2-1.html)
- [Addon文档](https://learn.microsoft.com/zh-cn/minecraft/creator/reference/content/itemreference/examples/itemcomponentlist?view=minecraft-bedrock-stable)

为了确定问题是由附加资源包独立引起的，还是由 “重复定义相同实体” 这一动作引起的，需要先进行实验：
- step1: 清空附加资源包内的所有模型和贴图，如果加载仍然很慢，那么不是由模型和贴图引起的。
  实验表明，清空所有模型、贴图和 `render_controller` 后，加载速度明显更快了
- step2: 尝试缩小范围，分别删除模型、贴图和`render_controller`。
  删除【贴图】，但不删【`render_controller`、模型】，加载速度正常。
  删除【`render_controller`、模型】，但不删【贴图】，加载速度正常。
  删除【`render_controller`】，但不删【贴图、模型】，加载速度正常。
  删除【模型、贴图】，但不删【`render_controller`】，加载速度正常。
  删除【模型】，但不删【`render_controller`、贴图】，加载速度正常。
  删除【`render_controller`、贴图】，但不删【模型】，加载速度正常。
  这个结果很诡异， **加载速度变慢似乎是由多方面因素共同引起的，模型、贴图和`render_controller` 三者缺一不可。** 或许是三者凑齐才会正常加载资源，这需要进一步定位。
- step3: 到达瓶颈，现有实验无法指向明确的下一步，接下来只能进行一些启发式的探索了。
  - 在实验后，发现了两个加载时间较高的模型包（无模型包加载基线15s），其中碧蓝航线模型包较为精细，或许是原因之一。
  ```
  // 略卡（23s） ！耗时最高，重点排查
  "controller.render.touhou_little_maid.pack_azuru_line",
  // 略卡（19s） ！耗时次高
  "controller.render.touhou_little_maid.pack_make_sd_workwork"
  ```

#### 支持动画（一期）

定义一组动画，然后在特定的包id和皮肤id使用。
输入是个问题，增加了动画的指令会更长。所以偏向于靠纯资源包定义动画。


#### 支持语音（二期）

语音实际上和动画的关联不大，但是对于使用者来说，连续的两次更新意味着频繁生成皮肤包。
