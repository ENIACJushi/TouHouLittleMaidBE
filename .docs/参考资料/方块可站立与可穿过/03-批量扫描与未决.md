# 批量扫描与未决

在 01 的单格规则之上，若用「一次查出体积内非空气坐标」之类批量接口加速，正确性仍受下列约束。本篇不依赖具体工程模块名。

---

## 1. 空气 / 非空气 / 未知

批量接口在「允许未加载体积」时，通常**只返回已加载部分的命中格**。未加载格与空气一样不会出现在结果里，因此：

| 情况 | 应如何解释 |
| --- | --- |
| 已确认区块已加载，且该格未出现在「非空气」结果中 | **空气**（可当净空） |
| 区块未加载，或无法确认是否已加载 | **未知**：不建落脚点、不删已有点、不当空气 |
| 出现在「非空气」结果中 | **非空气**，再套 01 的可穿过 / 可支撑等 |

判定「已加载」应使用引擎提供的区块加载查询（或先把扫描体积裁成已加载子体积），而不是指望「允许未加载」开关本身去区分空气与未知。该开关只决定未加载时**抛不抛错**。

体积越过世界高度等边界前须钳位，否则整次查询失败。

**验收建议：** 在「已加载」掩码内，批量非空气集合应与逐格读取一致后，才把掩码内「未命中 = 空气」当作可靠。

---

## 2. 从「非空气列表」推属性时

01 已否决「用实心 / 薄片名单猜测代替读格」。批量优化时：

| 格子 | 允许做法 |
| --- | --- |
| 掩码内空气 | 不读实体；属性按空气 |
| 类型已在「与状态无关」白名单中 | 可用该类型预计算的 01 结果 |
| 活板门等依赖状态的类型 | **必须**读该格实体与状态 |
| 非空气但未入任何分组 | **必须**读实体再套 01，**禁止**直接判不可过 |

原版反例（非空气、常非实心、不在薄片名单 → 01 默认**可过**）：光方块系列、结构空位等。若写成「非空气 ∧ 非薄片 → 墙」会与 01 冲突。

类型名单若从规则生成，应以 **01 中的同一批分类**为唯一来源，避免手写第二份名单日后漂移。

| 打开活板门的侧站、楼梯攀爬 | 特例；普通平移边勿盲信；中长期可用脚本贴面/挪位 |
