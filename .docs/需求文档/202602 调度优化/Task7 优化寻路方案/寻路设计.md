# 寻路基建

先把需要反复寻路的工作共用的那套结构定下来，再把农作等模式接上去。

## 寻路原则

- 农作这类工作会不停找下一格，而且**一个目标只能由一个女仆认领**。方块信息和「哪些落脚点互相走得到」要共用，避免每个女仆反复读同一片地。
- 持续工作只用**来回都走得通**的步。女仆从 A 去 B，从 B 也要能回到 A，否则不去 B。平地互走、跳上一格再落下一格，算来回都通。落下两格及以上跳不回去，不进这套共享数据。
- 一次性寻路不进共享数据，用完即弃，允许落下多格。跨沟属于可逆步，进共享数据。
- 水能不能站是寻路基建的统一设定，所有工作模式相同，不按工作单独放宽或收紧。场因此可以共用。

真正卡住女仆的不是寻路步数，而是她被允许活动的那一圈：

- 家模式以家的坐标为中心。女仆和 NPC 以外的状态，回家范围是水平各 32 格的方框，出框或换了维度会被传送回家中心。NPC 的这个方框只有 2 格。
- 跟随主人时，以主人位置为中心，超出距离同样不应把圈外的点当成目标。

圈外的落脚点可以留在共享数据里（别的女仆、别的家用得上），但**这个女仆不能认领圈外的点**。这一圈只限制目标，不限制路怎么绕，所以圈外的格子可以作为途经格。

从这一次开始寻路，到她抵达目标的整段时间里，不执行回家传送。这段时间包括算出路、出发之后的平走、跳上、落下、跨沟，以及人还在沟里或空中的时候。抵达、取消或走路失败，这段才结束。结束之前，即使人已经在活动圈外的途经格上，也不把她拉回家中心。

认领仍只选圈内目标。场牌可认领时只比较场编号，不在认领时把路找出来。出发找路可以走出这一圈（途经格不受圈限制），但每一步都要算进这一拍的预算，不能因为「已经是同一场」就把步数放开。

## 落脚点表

所有工作模式共用一张表，按 **维度 → 区块 → 落脚点** 存放。区块内用一张坐标表直接找到落脚点，不按高度分层，也不按竖列分组。

要查的是某一个坐标、它旁边几格，以及方块改动时同一竖线上大约三个高度。这些都是点查。平走的邻居虽在同一高度，仍然是查旁边那几格，不必扫整层。一块耕地往往有上百个落脚点且几乎同一高度。按竖列会为每个落脚点各做一张只有一项的表，对象开销大一个数量级。

以后若「按高度列出这一区块的全部落脚点」真成了热路径，再加一张高度索引。主键不要改成竖列。

每个落脚点记三样：

- 这一格现在还能不能站。
- 可逆邻居，并且**带走法**：平走、跳上一格、落下一格、跨沟。出发找路就沿这些邻居走，不再另推一套走法。
- 所属的场编号。

不在落脚点上记整条路，也不记「到每个目标的下一跳」。一片田上千个落脚点、再乘上多个目标，完整路径会到几十兆，挖掉一格还要整片作废。绕到区域中心再走去目标的树很省，但隔壁一格会绕整片田，农作不能用。

也不另存「刚走过的那几条路」。农作几乎每次都是新目标，收割本身又会改方块，这份缓存对不上，还会在每次改地形时被整份扔掉。出发时按下面的预算现算即可。

## 可达场

场是落脚点用可逆步连成的一片。同一场里任意两点都能经过若干次可逆步互相走到。场在所有工作模式之间共用，世界上可以同时有多片。

可逆步只包括：

- 双向平走。
- 成对的跳上一格和落下一格（低的那一侧头顶要空，才能跳回去）。
- 跨沟。空沟两端都能落，来回就是同一条沟，与双向平走相同，不再额外要求「扫描时两侧谁先被选中」。有一格高差时，与跳上、落下相同，只要求低的一侧头顶能跳回去。

写入跨沟之前要验证反向：两端都能落，高差至多一格，低的一侧头顶能跳回去。验证失败就两边都不写入。高差两格及以上的沟不算可逆步。每个方向只留最近一跳、且先试平跳再试低一格，可能先扫出单行边；那是生成顺序问题，验证通过后按沟的两端成对写入。落下两格及以上不进场。

每个落脚点只记能不能站、可逆邻居、场编号。每片场另有一张场牌：可认领，或暂停。染色进度不写在落脚点上，认领不读它。并查集不参与认领，也不用来拆场。

**第一次用到一块区块。** 按这一拍的预算读出能站的格子，写上可逆邻居。旁边区块还没建好的边先不连，等那边建好再按加边处理。这块里新长出来的一片，若只碰到一个已有场，直接写上那个编号，已有场不用暂停。谁也不碰就发一个新编号。这些编号写完的那一拍，场牌改为可认领。在此之前，认领对不上这些点。

**什么时候重读方块。** 不订阅玩家的破坏或放置，脚本改方块的当时也不重算。落脚点一直留着上次写上的邻居和场编号，直到有人要用它。

要用到某个落脚点时，才重读决定它的那些方块：这一格能不能站，以及它同一行、同一列上、不超过可逆步最远距离的邻居。斜角不读。半径外的叶子不改。同一拍里同一个落脚点只重读一次。

出发找路每扩展到一个落脚点，先做这次重读，再沿更新后的邻居走。认领不沿路重读，只用叶子上已经写着的场编号和场牌。所以刚收完的作物，在还没有寻路扩展到旁边这些落脚点之前，场保持原样。

重读之后只看这个落脚点的可逆步：

- 没增也没减：到此为止。不暂停、不染色、不换场编号。收掉作物再种上，脚下的土和周围的步都还在，就是这种。别的女仆照常认领。
- 只多了步、没有步消失：两端已经是同一场，什么都不用做。不是同一场，只把落脚点更少的那片改成更多的那片的编号，大的那一侧不用重写。这一拍改得完，认领不会看到暂停。改不完，两张场牌都先暂停，最后一笔写完的那一拍一起恢复。不能只暂停小场，否则认领会看到一半新编号、一半旧编号。
- 有步消失：先不改叶子上的编号。从断开处还站着的两端出发，沿现有邻居看它们还能不能走到一起。格子田挖掉中间一格、旁边绕得过去，通常很快碰上：没裂开，编号不动，场牌保持可认领。这一拍既没碰上、也还没分出完整的一侧，场牌改为暂停，下一拍接着走。某一侧已经走完，另一侧的端点还没走进来，走完的那一侧是裂出去的完整一片，只把这一侧写成新编号，大的一侧留旧编号。

重读时若发现踏脚没了，同一行或同一列上可能多出一条新的跨沟。染色和探测都走更新后的邻居，所以新沟可以把两侧重新连上，场可以不裂。不要在探测之前按旧编号先合并。

染色进行中，后续重读又发现步增减，这一轮账本作废重来，场牌继续暂停。叶子上的编号等这轮有了结论再一起改。

同一场且场牌可认领，就说明两点之间有可逆的路。认领不需要先把路找出来。场牌暂停，或这一圈的边还没对完，这场里的目标这一拍全部不选。别的场不受影响。已经出发的那一段路不因为暂停而改编号。

具体走法在出发时沿着可逆邻居找。找的时候用叶子上的邻居，目标在圈内，途经格可以在圈外。每一步计入这一拍的预算。平地走向附近目标通常在预算内能算完；路若在整片场里绕远，预算用尽就停。找路的结果：

| 结果 | 含义 | 怎么处理 |
| --- | --- | --- |
| 拿到路 | 每一步都是当前这场里的可逆步；目标在圈内，途经格可以在圈外 | 可以出发 |
| 证明走不到 | 这一代落脚点里，预算内确实没有路能到这个目标 | 这一拍不出发。不据此拆场；场只在上面的删边探测里裂开 |
| 不知道 | 区块还没加载好，或这一拍预算用尽 | 这一拍跳过。只给这个女仆记一次短的「未知」，不改场 |

目标被活动圈限制，路可以绕出这一圈。预算用尽不是「这格走不到」，只是这一拍不出发、也不拆场。下一拍可以再试。不回家传送的区间见上文：从这次开始寻路，直到抵达目标；取消或走路失败也同样结束这段，避免人在圈外的途经格上被拉回家。

追逐超时、互相堵住、路点名额用完，是走路失败，只禁止这个女仆短时间内再试这个目标，不改场编号。不要把堵车写成「这格走不到」。

出发前，场编号和现算必须都同意。现算过程中的重读若改了场，这场暂停或编号对不上，这一拍不出发。出发之后这一段路按已经算好的走法走完，走路期间不再逐格重读方块。中途地形变了，要等这次行走结束、取消或失败之后，下一次寻路才会看见。人在沟里、水里、空中时，脚下没有落脚点，不要沿用上一个场编号。

## 目标点

目标由工作模式自己维护：要去哪一格、谁占着。它不是落脚点的属性。作物格要先换成脚下那块可站的土，再问这张表。

认领顺序：

1. 目标在活动圈内，且没被别的女仆占着。
2. 脚下和目标的场牌都可认领，且场编号相同。同一场即有路。场牌暂停，或这一圈的边还没对完，这一拍不选这场里的目标。

出发时再沿着可逆邻居找出具体走法，并受出发找路自己的那一拍上限限制。目标在圈内，途经格可以在圈外。上限用尽则这一拍不出发。建区块、合并编号、删边探测都不占用这份上限。

脚下落脚点全项目只用这一条，视脚所在的方块而定。脚所在格的顶面低于整格、人会陷进去（耕地就是这样），这一格又能站，落脚点就是这一格。脚所在格顶上是空的，人站在下面那块完整方块的顶面上，落脚点是下面那一格。锚点、起点、作物所对的土，都先得到同一个脚位再套这条，不能各写一套。

## 维护

没有「方块一改就标脏」的队列。更新只发生在用到该落脚点的时候，规则见「可达场」。不要定时重读全部落脚点，也不要在收割当时重算。

收割的常见情况要等下一次寻路扩展到旁边的落脚点才会被看见。重读之后步没变，就不染色、不暂停。整场暂停只出现在两片场合并却一拍写不完，或者删边之后这一拍既绕不过去、也还没分出较小的那一侧。

建区块、合并编号、删边探测、出发找路各有自己的一拍上限，按这件事自己的规模来定，不共用一份。某一件用尽，只停这一件，不能把别的额度拿来补。

| 事情 | 这一拍最多做多少 | 用尽了 |
| --- | --- | --- |
| 建区块 | 新建的落脚点 | 这块先不可认领，下一拍继续建 |
| 合并编号 | 改写成同一编号的落脚点 | 两张场牌都暂停，下一拍继续改 |
| 删边探测 | 沿邻居走过的落脚点 | 场牌暂停，下一拍继续走 |
| 出发找路 | 这一名女仆这次扩展的落脚点 | 这一拍不出发，不改场 |

区块从这张表拿掉，按整块进行。脚本侧不一定有「区块卸载」事件，不能依赖它。一块区块同时满足两条才丢掉：已经一分钟没有被寻路用到，并且它不落在任何女仆的活动圈里。活动圈就是家框或跟随主人的那一圈，和玩家在不在旁边无关。丢掉之后，块外因此失去邻居的点，当作删边的两端，用同一套探测处理，不要把邻块上的整片场直接作废。

水能不能站由寻路基建定死，所有工作共用这一判定，不按工作推导。表里记的是同一套结果：能不能当地面、能不能穿过、按这个设定算不算危险、因此能不能当落脚点。

## 和一次性寻路的边界

落下两格以上只允许即用即弃的那次寻路使用。那次寻路不读、不写落脚点表和场编号。跨沟进场。

工作模式默认不走这一条。若以后允许用一次性寻路跳进低一层的田，落地的那一格在成为可逆落脚点之前，不得并进工作用的场。

## 附录：和现有代码的对照

只在改代码时用。

| 文档里的说法 | 现在的代码 |
| --- | --- |
| 落脚点、能不能站 | `StandableCache` / `SharedStandable` |
| 现有的「哪些站立点到得了某个目标」 | `ReachabilityField`，按目标存集合，不存路，大约 10 秒过期 |
| 全边寻路（含落下多格、跨沟） | `AStar` + `expandEdges`，展开大约 2000 步或 50 毫秒 |
| 出发后怎么走 | `Executor`：平走会抽稀，跳上和落下交给追逐，跨沟用冲量 |
| 走路失败后短时间不再试 | `UnreachableCache`，按维度、女仆、终点，大约 30 秒 |
| 回家传送 | 家坐标水平各 32 格的方框（NPC 为 2 格），出框或换维度传送回家中心。从这次开始寻路到抵达目标的整段时间不执行，含走路、跨沟和滞空；抵达、取消或失败后恢复 |
