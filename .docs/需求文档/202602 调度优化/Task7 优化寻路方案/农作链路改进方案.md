# 农作链路改进方案

Bedrock：`Farm.ts` + `Path.follow`。对照 Java：`.ref/TouhouLittleMaid-1.20` 的 `IFarmTask` / `MaidFarmMoveTask` / `TaskNormalFarm`。

| 项 | 现状 |
| --- | --- |
| 怎么走到作物旁 | 自己规划路径，走到后用「完成回调」通知农作逻辑去收或种 |
| 一次最多记下多少格 | 25 格，扫满就停 |
| 搜索半径 | 女仆周围约 ±15 格 |
| 跨维度误判不可达 | 已按维度分开记录，日常几乎遇不到 |

## 现状

耕地模式已经不再刷「农作标记实体」。流程是：在附近找成熟作物和空耕地 → 判断女仆走不走得到 → 派一条路过去 → 走到后再收割或补种。主流程是通的。

仍有这些问题，都是对着现有逻辑核对过的：

1. 走路刚结束、完成通知还要晚一帧才执行时，调度心跳可能抢先把同一格收掉一次，完成通知再收一次，同一格被处理两遍。
2. 女仆已经无效、或已经切出耕地模式时，格子占用不会被解开。别的女仆会一直以为这格有人在去，再也选不了。
3. 人已经站在田中间时，每一轮只收身边 1 格就停，密田要等下一次心跳（大约 3 秒）才能再收下一格。
4. 选点时先算一遍「能不能走到」，真正出发时又算一遍路，同一段路算了两次。
5. 火炬花这类「没有成熟状态字段」的作物，扫描时可能直接中断整次搜索，后面的田都扫不到。
6. 女仆从坐下站起来时，会重新挂上旧的「耕地索敌」行为；耕地模式本身又会立刻卸掉它。两边对着干，和「不再用索敌做农作」的设计不一致。

## 1. 现在怎么干活

调度大约每 3 秒给耕地模式一次心跳，大约每 9 秒再做一次正式搜索。

1. **搜索**：连续很多次都找不到足够目标时会变慢（缺目标节流）。范围内扫耕地和作物，记下候选格。
2. **选点**：先给这批格子算一张「从哪些站立点能走到」的共享图，再按离女仆的水平距离从近到远试。走得到且已经在身边：当场收/种。走得到但还远：占住这格、记在女仆身上、出发。
3. **走到之后**：完成则收/种，然后放开格子，立刻再找下一格。失败则只放开格子并再找。玩家取消或切模式则只放开，不再自动派下一格。
4. **心跳兜底**：正在走路时什么都不做。身上还有任务、而且人已经靠近：补做一次收/种（防止完成通知丢了）。人空闲：再派一格。人还没靠近时**不要**清掉任务，否则会漏收。

作物种类、成熟状态、种子和耕地的对应关系，写在数据包式的作物表里（原版、农夫乐事等）。另有一份「农作数据管理器」还没接上，现在不起作用。

## 2. 问题清单（按影响）

| 影响 | 玩家/女仆会看到什么 | 为什么会这样 | 建议 |
| --- | --- | --- | --- |
| 高 | 同一格被收或种两次，掉落重复或空地被种两次 | 走路结束的瞬间，心跳和「走完通知」都能动手 | 同一格同时只允许一处动手；走完通知还没跑时，心跳不要再收 |
| 高 | 某格永远没人去收，像被隐形占用 | 女仆消失或切走耕地时，提前返回，没解开格子占用 | 无论成功失败都要解占用；切模式、女仆卸载时一并清掉身上的农作任务 |
| 高 | 站在成熟田中央，收得很慢，一格一格等 | 已经在身边时，处理完 1 格就结束本轮 | 人还在身边就连续收，直到身边没有可收的，或本轮有上限 |
| 高 | 背包没种子也会跑去空耕地，到了种不上再跑下一格 | 选「该补种的空地」时不看背包里有没有对应种子 | 开扫前先记下背包种子；没有能种这格的种子就不要把它当目标（Java 版就是这样） |
| 高 | 远处有成熟作物，女仆却去扫到的前 25 格里较远的空地；成熟和空地只比谁更近 | 扫满 25 格就停，顺序取决于扫描方向，不是「离我最近」；排序只看距离，不区分收和种 | 按距离保留最近的一批；成熟作物优先于空地补种 |
| 中高 | 女仆多、田大时选路变卡 | 先问「能不能到」，出发时再完整规划一次 | 规划一次，选点和出发共用这份结果 |
| 中高 | 田里有火炬花时，整片搜索可能失败 | 成熟判断假定每种作物都有状态表；火炬花没有 | 没有成熟状态表就当成「看到就能收」；单格出错不要毁掉整次扫描 |
| 中高 | 站起来后短暂出现旧索敌，和耕地脚本抢控制 | 站立会按模式重新挂行为组件；耕地脚本随后又卸掉耕地索敌 | 耕地模式站立时不要再挂旧索敌，只保留脚本派路 |
| 中 | 女仆停在半路，身上还记着一格，之后再也不搜新目标 | 有未完成任务时搜索直接跳过；心跳又只处理「已经靠近」的任务。若走路异常结束且没通知，任务会一直挂着 | 连续多次心跳：人没在走、也没靠近目标，就作废这格并重新搜索 |
| 中 | 空手收小麦会把作物拆掉；干完一格常跑回脚边再找，来回折返；作物正下方不好站时判定走不到 | 收割只有「破坏方块」一种；每次都从脚下重新扫；只认作物正下方那一格能不能站 | 见下一节 Java 手感：锄头才破坏，否则收完把年龄打回 0；记住上一格附近继续找；旁边一格能站也算到得了 |
| 中 | 加一种新作物要改核心农作代码；瓜、甘蔗、可可仍靠标记实体索敌，和耕地不是同一套走法 | 作物表是手写脚本，空的数据管理器没接上；那三种模式还是旧目标实体 | 作物用「数据 + 各自的收/种规则」扩展；瓜/甘蔗/可可改成同一套「走到再动手」 |
| 低 | 头顶被挡住仍去种；类型检查被关掉，改农作容易引入隐蔽错误；没种子时空地被反复扫描 | 不检查作物上方是否有空间；农作文件关闭了类型检查；补种失败的冷却主要针对「已知该种哪种」的失败 | 上方不空就跳过；恢复类型检查；背包没有种子时进入慢扫描，而不是空转 |

## 3. Java 版里值得学的做法

Java 版把「普通农田、甘蔗、瓜、可可」分成不同工作，而不是塞进一个函数。普通农田里，地狱疣、稻等特例再挂到农田上，不必各开一个模式。

### 宜借鉴

- **能不能收、怎么收、能不能种、怎么种**拆开。扫描只问「这格要不要去」，走到了再执行动作。
- 记的是**耕地那一格**（脚底下的土），作物在它上面。走到后同一刻：能收先收，拆掉之后同一刻再补种。若收割只是把年龄打回 0、作物还在，就不必再种。
- 开始找目标前，先把背包里的种子列出来。这一格能收就去收；不能收，再看这些种子里有没有能种在这格土上的。
- 特例作物（地狱疣、稻）注册进普通农田；瓜、甘蔗、可可保持独立工作，只复用「怎么走、怎么判定靠近」。
- 成功干完一格后，下一轮从**这一格附近**继续找，而不是总从脚下重来。找路时，目标旁边一小块里任意一格能走到，就算这格可作业。搜索本身有冷却，避免每刻都扫全田。
- 主手拿锄：破坏作物。没拿锄：掉落进背包（或等价掉落），并把生长年龄设回 0，田还在。多近算「到了」按作物不同，大约 1～2.5 格。

### 不要照搬

- Java 用大脑记忆「当前目标点」。基岩继续用「身上记一格农作任务 + 走完再通知」即可。
- Java 靠原版「这是不是作物、这土能不能长这种子」自动识别。基岩没有这套接口，继续用作物表（方块、成熟状态、种子、耕地）是对的。
- Java **没有**多女仆抢同一格的占用表，两人可能奔向同一格。基岩的格子占用是加强，应保留，并把上面的「不解占用」修好，不要为了和 Java 一样而删掉。
- 基岩现在追的是作物方块本身。可以改成追耕地，和 Java 一样，收和种都相对「土上面那一格」，逻辑更对称。这是可选整理，不是当前故障。
- 掉落直接进女仆背包、以及「女仆踩不坏耕地」，在基岩脚本里能力有限。现有「破坏掉落」和「指定战利品表再放回未成熟方块」可以保留。

## 4. 建议拆成的职责

不要再把扫描、走路、收种写在同一处里缠在一起。建议五层，名字只是职责，不是必须的类名：

1. **作物表**：这种方块成熟长什么样、用什么种子、种在什么土上。
2. **作物规则**：个别作物怎么判断成熟、怎么收、怎么种（火炬花、地狱疣这类）。
3. **计划**：在范围内找出候选、排序、占用格子、决定下一格。
4. **动手**：人已经在旁边时，真正改方块（收、种、补种）。
5. **走路**：只负责走到指定点，走完、失败或取消时通知农作。

和 Java 的分工相同：一个负责「找下一格并走过去」，一个负责「到了就收/种」。不必再做一套大脑系统。

默认选下一格的顺序：

1. 先看背包里有哪些种子。
2. 扫出候选，成熟作物排在空地前面。
3. 去掉已被别人占用的、补种冷却中的、以及没有种子可种的空地。
4. 自己或旁边一格能走到，才算可达。
5. 在可达里挑最近的；若刚在附近干完活，稍微偏向那一片。
6. 已经在身边就动手，否则出发。

## 5. 分阶段落地

| 阶段 | 要达到的效果 | 做什么 | 怎么验收 |
| --- | --- | --- | --- |
| A · 正确性 | 不收两次、格子不会永久被占 | 同一格同时只动手一次；任何退出都解开占用；没种子不去空地；没有成熟状态的作物不打断扫描；站起来不再挂旧耕地索敌 | 同一格不会双份掉落；切模式或女仆消失后再来的女仆还能选这格；有火炬花的田能扫完 |
| B · 速度 | 站在田里连续收，选路少算一次 | 身边能收就连着收；规划结果选点和出发共用；成熟优先；按距离留最近的一批而不是扫到 25 个就停 | 站在成熟田中央会连续收割；同样田地里寻路计算变少 |
| C · 手感 | 更接近 Java 版农田 | 拿锄才拆作物，否则收完留茬并把年龄打回 0；头顶挡住不去；旁边能站也算到得了；记住上一工作点；卡住的任务超时作废 | 空手收麦田还在；作物正下方是坑时仍能从旁边收；半路丢通知后会自己重新找活 |
| D · 扩展 | 加作物不动核心流程 | 作物表和个别规则分开；未接入的空数据管理器要么接上要么删掉，只留一份作物数据 | 新作物只加数据和规则说明 |
| E · 其它农作 | 瓜、甘蔗、可可和耕地同一套走法 | 不再为它们刷标记实体再靠索敌打到 | 这三种也是「走到再动手」 |

## 6. 建议先做哪几件

- **先做**：同一格不要被处理两次；退出时一定解开格子占用；没种子不去空地；火炬花这类不打断扫描；站起来不要挂回旧耕地索敌。
- **接着**：身边连续收割；选路只规划一次；成熟作物优先，并按距离取最近的一批。
- **再接着**：旁边能站就算到得了；锄头才破坏、否则留茬；记住上一格附近继续干；半路卡住的任务超时作废。
- **最后**：作物规则可插拔；瓜、甘蔗、可可改成同一套走到再动手。
