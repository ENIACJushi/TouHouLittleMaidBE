# 目标点推动女仆：碰撞相关实体组件

现象：女仆靠近 `thlmt:seek_marker` 时会被目标点推开。本文整理基岩版实体组件里和碰撞、互推、击退相关的项，并对照当前定义判断哪些值得试。

组件名单来自 [Entity Components 列表](https://learn.microsoft.com/zh-cn/minecraft/creator/reference/content/entityreference/examples/componentlist?view=minecraft-bedrock-stable)（stable）。字段说明来自对应英文条目。

## 当前定义

`thlmt:seek_marker`（`format_version` 1.12.0，`entities/maid_target/seek_marker.json`）已经关掉：

| 组件 | 现值 |
| --- | --- |
| `minecraft:collision_box` | `width` 0，`height` 0 |
| `minecraft:physics` | `has_collision` false，`has_gravity` false，`push_towards_closest_space` false |
| `minecraft:pushable` | `is_pushable` false，`is_pushable_by_piston` false |
| `minecraft:knockback_resistance` | 1.0 |
| `minecraft:damage_sensor` | 全部伤害 `deals_damage` false |

`thlmm:maid` 根组件同样是零碰撞、不可推、无重力。真正走路时走的是事件 `become_maid` 挂上的 `thlmm:maid_basic`，它会盖掉根组件：

| 组件 | `thlmm:maid_basic` |
| --- | --- |
| `minecraft:collision_box` | `width` 0.6，`height` 1.5 |
| `minecraft:physics` | `{}`（三项都回到默认：有碰撞、有重力、不往空隙里挤） |
| `minecraft:pushable_by_entity` | `{}`（默认可被其它实体推） |
| `minecraft:pushable_by_block` | `{}`（可被活塞、潜影盒推） |

因此：目标点声明自己不被推，女仆声明自己可以被别的实体推。推动组件只约束拥有者能不能被推，不约束它会不会把别人推开。

## 女仆模板已升到 1.26.30

改动在 `MaidGenerator/template.js`。`entities/maid/maid.json` 由 `npm run build` 生成，这次没有改它，需要重新生成后才会带上新格式。

旧 `minecraft:pushable` 已按原布尔值拆开：`is_pushable: true` 变成空的 `pushable_by_entity`，`false` 变成 `presets: [{ push_mode: "none" }]`；`is_pushable_by_piston: true` 才挂 `pushable_by_block`。这次只做格式迁移，没有加「路点不推女仆」的过滤器。

未升到 1.26.40。该版本会收紧 `on_death`、`jump.static`、`persistent`、`behavior.beg.look_time`、`behavior.ranged_attack` 等字段，女仆现有写法要再改一轮才过得去。

## 版本门槛

`format_version` ≥ 1.26.10 之后，`minecraft:pushable` 不再被解析，拆成 `minecraft:pushable_by_entity` 与 `minecraft:pushable_by_block`。`presets` 写法从 1.26.30 起是正式格式。女仆模板已经升到这个版本；生成出的 `maid.json` 以及 `thlmt:seek_marker`（仍是 1.12.0）还没有跟上，路点上的新组件不会生效。

## 和互推直接相关

### `minecraft:collision_box`

碰撞箱宽高。负值当 0。默认约宽 0.6、高 1.8。近战和投射物的命中箱是另一套（见 `custom_hit_test`）。

双方都有碰撞箱时，引擎用它做实体间推挤。路点已经是 0×0。若游戏里仍被推，零尺寸没有消掉推动，继续把路点宽高改成更小的数没有新信息。

### `minecraft:physics`

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `has_collision` | true | 是否与物体碰撞 |
| `has_gravity` | true | 是否受重力 |
| `push_towards_closest_space` | false | 卡进方块时是否被推向最近空隙 |

区域效果云用 `has_collision: false` 作为「不撞东西」的范例。路点已经是这个值。`push_towards_closest_space` 处理的是卡在方块里，不是实体互推；路点和女仆当前都是 false。

### `minecraft:pushable`（&lt; 1.26.10）

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `is_pushable` | true | 能否被其它实体推动 |
| `is_pushable_by_piston` | true | 能否被活塞安全推动 |

只描述「谁能推我」。路点 `is_pushable: false` 只保证路点自己不被女仆挤走，不保证女仆不被路点挤走。女仆 `maid_basic` 显式打开了 `is_pushable`。

### `minecraft:pushable_by_entity`（≥ 1.26.10）

实体被其它实体推动时的规则。`presets` 按顺序取第一个过滤器命中的项；都不中则用默认推动。

和本问题直接相关的字段：

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `push_mode` | `default` | `none` 表示不能被推；另有 `default`、`legacy_boat`、`legacy_minecart`、`ball` |
| `push_scale_self` | 1 | 碰撞时自己被推开的比例，0 为不推开自己 |
| `push_scale_other` | 1 | 碰撞时施加给对方的推力比例，0 为不推对方 |
| `require_collision_overlap` | true | 为 true 时碰撞箱不重叠就不施力 |
| `min_distance` / `max_distance` | 约 0.01 / 极大 | 两实体中心水平距离在此区间内才施力 |
| `strength_multiplier` | 约 0.05 | 推力倍率 |
| `filters` | 空 | 可按 `is_family` 等只对某一类对方生效 |

这是名单里唯一能按对方家族关掉「我被谁推」和「我推谁」的组件。官方船对硫磺立方用了 `push_mode: "none"` 的过滤器写法。

### `minecraft:pushable_by_block`（≥ 1.26.10）

被活塞、潜影盒等方块推动。与路点互推无关。升版后若要保持「不可被活塞推」，需要显式不挂这个组件（旧字段 `is_pushable_by_piston: false` 不会再被读）。

### `minecraft:is_collidable`

让其它生物和本实体发生竖直、水平硬碰撞。双方都必须有 `collision_box`，且只在生物之间生效。文档写明：对会移动的 collidable 生物不可靠，建议只用于静止实体。和 `is_stackable` 是一对：本组件管「别人怎么撞我」，`is_stackable` 管「我和同类怎么撞」。

船使用空对象开启。当前女仆和路点都没有这个组件。普通生物互推不依赖它。给路点加上会变成硬阻挡，和「不要挡路」相反。

### `minecraft:is_stackable`

同类实例之间的竖直、水平碰撞。`value` 默认 true。只影响同一实体种类，管不到女仆与路点（二者 identifier 不同）。

### `minecraft:push_through`

`value` 默认 0，单位为方块，表示实体能挤过去的距离。没有过滤器，改的是这个实体对一切阻挡的挤过能力，不是只对路点。

## 和「被打一下弹开」相关，但是另一条通路

若观察到的位移发生在近战命中瞬间，而不是贴着路点走的全程，更像击退而不是物理互推。

### `minecraft:knockback_resistance`

抵抗近战击退。0 为无抵抗，1 为完全免疫（铁傀儡）。1.26.20 起允许负值到 -2，负值会放大受到的击退。也可写成单个小数。

路点已经是 1，所以路点自己不应被女仆的近战打飞。写在路点上不会减少女仆受到的击退。写在女仆上会同时削弱战斗里受到的击退；女仆已有 `slot:knockback_0`～`slot:knockback_100` 按 0～1 分档，那是给别的系统用的。

### `minecraft:apply_knockback_rules`（≥ 1.26.30）

定义本实体打出击退的方式，不是自己被推的方式。`presets` 可用 `filter` 按对方类型分支。`horizontal_power` 默认 1，`vertical_power` 与 `vertical_velocity_cap` 默认约 0.4，`knockback_mode` 为 `relative_horizontal` 或 `hit_direction`。

只有在确认位移来自女仆攻击路点时才有意义：给攻击者加一条「对方家族是 `seek_marker` 时水平、竖直威力为 0」的预设。它管的是打出去的击退，官方描述的承受者是目标，不是攻击者自己。

### `minecraft:custom_hit_test`

近战和弹射物的命中箱列表（`width`、`height`、`pivot`），与 `collision_box` 分开。缩小或清空路点的命中箱，可以让近战打不中，从而避开「命中瞬间的位移」。它不关闭物理推挤。

### `minecraft:attack` / `minecraft:damage_sensor`

攻击组件决定近战是否结算；`damage_sensor` 决定受到伤害时是否扣血、是否触发事件。路点已经不扣血。二者都不描述推挤向量。

## 名单里其余沾边、但解决不了「被目标点推」

| 组件 | 为何列出来 | 和本现象的关系 |
| --- | --- | --- |
| `minecraft:ground_offset` | 相对地面的竖直偏移，默认 0 | 改站立高度，不取消互推 |
| `minecraft:friction_modifier` | 地面摩擦倍率，1 为正常 | 只改摩擦。1.26.20 起只影响地面摩擦；更旧的格式会自动带上 `uses_legacy_friction` |
| `minecraft:variable_max_auto_step` | 自动上台阶高度，默认 0.5625 | 对方块台阶，不对实体 |
| `minecraft:can_climb` / `navigation.*` / `movement.*` | 攀爬与寻路移动方式 | 决定怎么走过去，不决定贴上目标后的推力 |
| `minecraft:projectile` | 弹道以及撞到方块、流体、实体后的反应 | 路点不是弹射物 |
| `minecraft:cannot_be_attacked` | 阻止被攻击，除非对方有 `ignore_cannot_be_attacked` | 只关攻击，关不掉物理推挤；若位移来自近战命中，可以当作旁路验证 |

## 哪些值得用

按「能针对路点、且和现有现象对得上」排序。下面几条彼此独立，没有游戏内对照实验前不要一起改。

1. **优先试：女仆侧 `pushable_by_entity` 预设。** 模板格式已经是 1.26.30。在 `thlmm:maid_basic` 现有的空 `pushable_by_entity` 上增加预设：对方 `is_family` 为 `seek_marker`（或 `thlmt:seek_marker`）时 `push_mode` 为 `none`，并把 `push_scale_self` 设为 0，后面再跟一条默认推动。这样玩家和其它生物仍能推女仆，只有路点不行。生成 `maid.json` 之后才会进游戏。
2. **路点侧再加一条，但路点仍是 1.12.0。** `push_mode: none`，`push_scale_other: 0`。拥有者是路点时，`push_scale_other` 才是「路点施加给女仆的力」。只改女仆、不改路点，仍然可能留下路点打出去的那一半力。路点要先单独升到 1.26.30，这条才会生效。
3. **路点旧开关已经用尽。** 路点的零碰撞箱、`has_collision: false`、`is_pushable: false` 都已设置。旧 `pushable` 没有「不要推别人」字段。若现象仍在，继续改这三个字段没有文档上的剩余旋钮。
4. **先分开现象再决定要不要动击退。** 若只在 `entityHitEntity` 那一拍被弹开，再考虑路点 `custom_hit_test` 收到打不中，或升版后用 `apply_knockback_rules` 对 `seek_marker` 把打出的威力设为 0。`knockback_resistance` 写在路点上已经是 1，再加大对女仆无效；写在女仆上会误伤正常受击。
5. **不要加 `is_collidable` / `is_stackable`。** 它们是额外的硬碰撞。路点加上会挡路；`is_stackable` 只作用于同类。
6. **`push_through` 只适合作为女仆侧的粗探针。** 它没有家族过滤，数值会作用到所有阻挡。可以用来回答「残留的是不是实体碰撞」，不适合作为正式修法。

先前短距 Gap 的结论是「对岸 marker 与落地躯体重叠互推」，处置是把 marker 沿跳向偏出碰撞半径并抬高（见 `短距Gap欠冲诊断/README.md`）。那是摆放位置绕开重叠。本文列的是定义侧还能不能让重叠本身不产生推力。
