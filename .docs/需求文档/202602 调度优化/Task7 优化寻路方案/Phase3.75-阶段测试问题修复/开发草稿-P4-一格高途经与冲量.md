# P4：一格高障碍 — 多余途经点与脚本 Jump1 冲量

## 现象

爬上一格高的台/台阶，原版 NAT 寻路本可自动迈上；当前路径在台阶附近仍会留下途经点，并常出现脚本 Jump1 冲量。

## 根因

1. **规划**：`expandEdges` 对邻格 `y+1` 生成 `Jump1` 边（连通性正确，应保留）。
2. **执行抽稀**：`buildFollowSteps` 只对连续 `Walk` 按 `VIA_STEP` 抽稀；**每个 `Jump1` 强制留一个 AI 途经点**（与 Fall 同等「全留」）。
3. 结果：平路上的一格台阶把「可抽稀的直行」打断成「…via → 台阶顶 via → …」，Seek 反复换点；一旦 AI 丢目标 / 停滞，早切 `ScriptFollow` 就会打出 `applyJump1Impulse`。

脚本冲量本身只应服务 **ScriptFollow 回退**（禁走后原版不再自动上台）；问题在于 **不该为普通 Jump1 强制插途经点**，从而放大回退概率。

## 方案对比

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A | 规划层删除 Jump1，只保留 Walk | 执行简单 | 丢代价区分；A* 可能绕更远 |
| B（推荐） | 规划保留 Jump1；执行把 Jump1 与同向 Walk **一并抽稀** | 原版自动迈步；少 via；Fall/Gap 不变 | 抽稀若跨过台阶，依赖原版上台（已确认可） |
| C | 保留 Jump1 via，但禁止 ScriptFollow 对 dy=1 冲量 | 减冲量 | via 仍密；禁走回退时 dy=1 可能卡死 |

## 推荐方案（B）

- `buildFollowSteps`：`Walk | Jump1` 视为「可行走段」，同一水平方向连续合并后 `sparsifyWalkIndices`。
- `Fall` / `SprintGap` 逻辑不变（落下与跨沟仍全留 / 独立）。
- `ScriptFollow` 的 Jump1 冲量**保留**（禁走态下仍需脚本上台）。

## 验收

1. 直行穿过若干一格台阶：途经点数量接近纯平地抽稀，不再每级一台一个 via。
2. FollowAI 段由原版迈上，无脚本起跳日志（除非真正落入 ScriptFollow）。
3. 真·跨沟 Gap 与多格落下行为与改前一致。
