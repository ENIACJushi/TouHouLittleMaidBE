# P3：目标调度 — 现状与优化方向

> 本项按草稿「先看清获取目标的整个逻辑」：先完整梳理，再给方案。  
> **已落地的小改**：Farm 选点 **收割优先于补种**（同距时）。  
> **认领 N / 身边连收 / 卡住 job 作废** 等需你拍板后再改（见文末）。

## 1. 端到端调用链

```
thlmm:t
  → MaidScheduleEvents.onTimer
      → 每次 ≈3s：MaidTarget.stepEvent → Farm/CropRoute.onSchedulePulse
      → 每 ≈9s：MaidTarget.search → Farm.search / createCropRoute().search
```

### Farm（耕地）

```
search
  ├─ isFollowing / 已有 farm_job → 直接 return
  ├─ SpeedController.beforeSearch（缺目标节流）
  └─ runJob: collectTasks(≤25) → assignNext

assignNext
  ├─ 门禁：follow / fieldUnknown / 活动圈 / standNodeFromFeet
  ├─ 过滤：cellClaims 空闲 + plant 有种子
  ├─ 排序：距离；同距 harvest > plant（本项已加）
  └─ 逐候选：活动圈 → classifyFieldClaim(same) → unreachable
        → reversiblePathResult → claimCell + writeJob + Path.followResult

onFollowComplete
  ├─ done → acquireAt；一律 releaseCell + 清 job
  └─ 非 cancel：再 collectTasks → assignNext

onSchedulePulse
  ├─ follow / hasPendingComplete → return
  ├─ 有 job 且 near → 补 acquire + 清 job
  ├─ 有 job 且 !near → return（不清，防漏收）← 卡住风险点
  └─ 空闲 → collectTasks → assignNext
```

### Melon / Cocoa / SugarCane

与 Farm **同构**，经 `CropRoute`：坐标认领 + Path.follow，**不再**刷旧 `thlmt:farm` 等农作实体。差异：落脚（旁格 / 甘蔗 drop2）、独立 `cellClaims` 与 job DP。

Path 层 `seek_marker` 是**寻路路点**（会话内 teleport），不是农作目标堆。

## 2. 数据结构（认领语义）

| 结构 | 含义 |
| --- | --- |
| `cellClaims: Map` | **单格**占用（1 女仆 × 1 格） |
| DP `thlm:farm_job` 等 | **单任务** JSON |
| `unreachableCache` | 按女仆+落脚点 ban |
| StandField 场牌 | `classifyFieldClaim`：same / different / unready / paused |
| 扫描上限 | Farm 25；瓜/可可 20；甘蔗 40 |

**没有**「一次认领 N 格」队列。

## 3. 与草稿两条方向的对照

| 草稿想法 | 现状 | 建议表述 |
| --- | --- | --- |
| (a) 认领一定量目标，防多女仆抢点 | 仅出发时锁 1 格；扫→认领之间有竞态窗 | 预占最近 N 格（仅坐标锁）；**N 与释放策略需定** |
| (b) 认领多个，到点后不删实体、挪到下一点 | 农作已无目标实体；Path marker 已 teleport | 改为 **任务队列 + 近距连做 / 短 follow**，勿恢复农作实体 |
