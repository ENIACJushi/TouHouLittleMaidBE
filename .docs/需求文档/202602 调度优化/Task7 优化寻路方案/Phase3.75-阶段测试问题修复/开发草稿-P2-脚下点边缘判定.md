# P2：女仆在方块边缘时脚下被判为空

## 现象

女仆站在方块边缘时，`standNodeFromFeet` 有时返回 `undefined`，起点校验失败，农作 / Path 整拍不出发。

## 根因

全项目脚位只走 `standNodeFromFeet`：对 `location` 做 `floor` 取一格，再按「耕地陷格 / 否则 y-1」求支撑。

引擎脚位是碰撞箱中心；宽 0.6 的实体可以**中心悬在邻格空气柱上方**，同时 AABB 仍压在实体旁实心块上（`isOnGround` 仍为 true）。此时：

1. `floor(feet.xz)` 落在空气柱；
2. `tryStandNode(空气柱下)` 失败 → 判「脚下为空」。

这不是谓词公式错，是**单点采样与碰撞支撑不一致**。

## 方案对比

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A | 中心失败后向四邻试支撑 | 简单 | 邻格可能不是实际承重面；斜向边缘易漏 |
| B（推荐） | 中心 + 碰撞足迹内多点采样（半径 = `MAID_COLLISION_RADIUS`） | 与实体真实承重一致；常量已有权威来源 | 每起点最多 9 次 tryStand |
| C | 向下射线 / getBlockFromRay | 贴近引擎 | API/性能不稳定；与「支撑格节点」模型耦合差 |

不采用「调大 floor 容差」一类拟合特例。

## 推荐方案（B）

1. 抽出单点逻辑 `standNodeFromFeetSample(cache, x,y,z)`（原 sunk / y-1 规则不变）。
2. `standNodeFromFeet`：先采样脚位中心；失败则在 `±MAID_COLLISION_RADIUS` 的 4 轴 + 4 对角共 8 点再试。
3. 多点都成功时，取水平距脚位中心最近的支撑格（稳定、可预期）。
4. 仍全部失败 → `undefined`（人真在空中 / 水里等，保持原语义）。

权威半径：`Arrive.MAID_COLLISION_RADIUS`（= JSON `collision_box.width/2`）。

## 验收

1. 站在方块棱/角上仍能得到支撑格，Farm.assignNext / Path.find 不再无故起不了步。
2. 站在完整格心时结果与改前一致。
3. 真悬空（脚下无承重）仍返回 undefined。
