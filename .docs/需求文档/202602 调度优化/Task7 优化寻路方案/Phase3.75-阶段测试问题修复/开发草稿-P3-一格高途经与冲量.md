# P3：一格高障碍 — 多余途经点与脚本 Jump1 冲量

**状态：不做（已回退代码）**

## 结论（实测）

曾试方案 B：规划保留 `Jump1`，执行层把同向 `Walk|Jump1` 一并抽稀，指望原版 NAT 自动迈上一格台。

实测：**连续越过两个一格障碍时，跳第二个容易卡死**。抽稀后中间缺少台阶顶 via，原版对「连续两级上台」不可靠。

因此 **不采用该方案**；维持原行为——`Jump1` 与 `Fall` 一样全留途经点。相关 `Executor` 改动已回退。

---

## 现象（原诉求）

爬上一格高的台/台阶，原版 NAT 寻路本可自动迈上；当前路径在台阶附近仍会留下途经点，并常出现脚本 Jump1 冲量。

## 根因

1. **规划**：`expandEdges` 对邻格 `y+1` 生成 `Jump1` 边（连通性正确，应保留）。
2. **执行抽稀**：`buildFollowSteps` 只对连续 `Walk` 按 `VIA_STEP` 抽稀；**每个 `Jump1` 强制留一个 AI 途经点**（与 Fall 同等「全留」）。
3. 结果：平路上的一格台阶把「可抽稀的直行」打断成「…via → 台阶顶 via → …」，Seek 反复换点；一旦 AI 丢目标 / 停滞，早切 `ScriptFollow` 就会打出 `applyJump1Impulse`。

## 方案对比（归档）

| 方案 | 做法 | 结果 |
| --- | --- | --- |
| A | 规划层删除 Jump1，只保留 Walk | 未试 |
| B | 规划保留 Jump1；执行与同向 Walk 一并抽稀 | **否决**：连续两级上台易卡 |
| C | 保留 Jump1 via，禁止 ScriptFollow 对 dy=1 冲量 | 未试；本任务整体不做 |

## 现行策略

- `buildFollowSteps`：`Walk` 抽稀；**`Jump1` / `Fall` 全留**；`SprintGap` 独立。
- `ScriptFollow` 的 Jump1 冲量仍仅服务脚本回退段。
