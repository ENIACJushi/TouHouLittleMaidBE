# P1：游戏重启后路点 / Seek 残留

## 现象

- `thlmt:seek_marker` 带 `minecraft:persistent`，脚本会话（`Executor.sessions`）只在内存里。
- 退档 / 重启后：会话没了，路点实体仍留在世界；女仆身上可能残留 Seek 档、追逐 / 目视组件组。
- 结果：幽灵路点、错误索敌、与 Movement 代理残留同类的异常态。

## 根因

| 层 | 现状 | 问题 |
| --- | --- | --- |
| 路点实体 | `persistent`，无 TTL | 无脚本持有时也不会消失 |
| 脚本 | `destroyMarker` 只在 teardown | 进程没了就跑不到 |
| 女仆 | onLoad 只清 `script_move` | Seek / pursue / look 不清理 |

## 方案对比

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A | 仅启动时扫世界删光 `seek_marker` | 实现简单 | 进行中异常退档后要等下次脚本启动；无「持有续命」语义 |
| B（推荐） | 路点倒计时自毁 + 脚本周期性续命 + 启动清扫 + onLoad 清 Seek | 与草稿一致；崩溃 / 重启都有兜底 | 多一层事件与 tick |
| C | 去掉 persistent，依赖区块卸载自然消失 | 改动小 | 卸载时机不可控；已存档实体仍可能残留 |

## 推荐方案（B）

1. **`seek_marker.json`**
   - 去掉 `minecraft:persistent`（临时路点不应跨会话持久化）。
   - 组件组 `ttl`：`minecraft:timer` 非循环，到期触发 `despawn`。
   - 事件 `ttl_start` / `ttl_renew`（remove+add `ttl` 重置倒计时）。
2. **脚本持有续命**
   - `ensureMarker` 生成后 `ttl_start`。
   - `tickAll` 每隔约 8s（160 tick）对仍有效的 marker `ttl_renew`。
   - marker 若已无效且会话仍在：按当前步重新 `ensureMarker`（防 TTL 竞态）。
3. **启动清扫**
   - 脚本初始化扫描已加载女仆时，顺带 `Seek.purgeOrphanMarkers()`（此时 sessions 必空）。
4. **女仆 onLoad**
   - `Seek.recoverResidual(maid)`：卸 pursue / look；若仍挂 seek 档则 `resetTarget` + `quit`。
   - **仅当 `!Path.isFollowing(maid)`**，避免区块短暂重载误卸正在进行的 follow（下一拍会由 beginStep/ensureSeek 重挂，但不如直接跳过稳妥）。

## TTL 参数

- 倒计时：**12s**（相对 8s 续命约留 4s 裕度）。
- 续命间隔：**160 tick（8s）**。

## 验收

1. follow 中途退出重进：世界中无残留 `seek_marker`；女仆无 seek 追逐残留。
2. 正常 follow：路点不因 TTL 中途消失（续命生效）；teardown 仍立即 remove。
3. 进行中 follow 时区块重载女仆：不因 onLoad 误卸 Seek 导致无故切 ScriptFollow。
