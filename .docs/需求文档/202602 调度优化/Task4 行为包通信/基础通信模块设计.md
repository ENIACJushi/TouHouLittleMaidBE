# Task4 基础行为包通信

多发送方（附加包）→ 单接收方（主包）。底层：`system.sendScriptEvent` + `scriptEventReceive`。  
控制面 `thlmc`，数据面 `thlmd`（与管理指令 `thlm` 分离）。

实现目录：`TouHouLittleMaid_BP/typescripts/src/controller/channel/`（已按本文实现；业务 topic 接线见后续）。

## 协议

### 控制面

| 事件 | 方向 | message |
|------|------|---------|
| `thlmc:register` | 副→主 | `uuid`（32 字符） |
| `thlmc:assign` | 主→副 | `senderId`(4) + `uuid`(32)，共 36 字符 |
| `thlmc:unregister` | 副→主 | `uuid`(32) |

**uuid（副包生成，进程内固定）**

- 长度：32；字符集：`0-9a-f`（小写，无连字符）  
- 生成：16 字节随机 → hex。Bedrock 无稳定 CSPRNG 时，可用 `Math.random` 拼 16 字节（附加包数量少，足够防撞）  
- 同一副包只生成一次；不要多个 `ChannelSender` 共用一个 uuid

**短 senderId（主包分配）**

- 4 位十进制 `0000`～`9999`；自增，`unregister` 后回池  
- 号池耗尽：忽略该 `register` 并打日志（不 assign）  
- 同一 uuid 再次 register：已有映射则重发同一 assign（幂等）  
- unregister 后再 register：可分到新号或复用空闲号（实现任选，副包以新 assign 为准）

**assign 截取（无分隔符）**

```
[0, 4)  → senderId
[4, 36) → uuid
```

副包校验 `message.length === 36` 且 `slice(4) === 自己的 uuid` 再采纳。

### 数据面

```
event.id      = thlmd:${topic}
event.message = senderId(4) + groupId(4) + total(4) + index(4) + chunk
```

- `topic`：`[a-zA-Z0-9_]{1,32}`  
- `groupId`：建议每条逻辑消息用**发送方侧递增计数**格式化为 4 位 hex（`0000`～`ffff`），避免纯随机撞号；同 sender 同时 in-flight 勿复用同一 groupId  
- `total` / `index`：4 位十进制；`index` 从 0 起；单消息最多 9999 片  
- 未分到短 id 前不发数据（只入队）  
- 单帧 message 保守 ≤2000 **字符**（实现时对非 ASCII 按 UTF-8 字节再收紧更稳）  
- 未知 / 已注销的 `senderId`：丢弃该帧

## 流程

1. 主包 `start()`：subscribe，维护 uuid↔senderId 与空闲号池；业务尽早 `on(topic)`。  
2. 副包生成 uuid，按下方策略 `register`。  
3. 主包分配短 id，广播 `assign`。  
4. 副包认领后停注册，发 `thlmd`；拼包键 `(senderId, groupId)` → handler。  
5. 一次性发完可 `unregister`；常驻包可不注销。

主包晚于副包：靠周期 register 接上。

### register 重试

**意图**

- scriptEvent 不排队：副包先发、主包后听时，首包会丢，所以必须能重发。  
- 加载后**立刻**发一次：主包已就绪时尽快拿到号，少等一轮。  
- 之后用间隔重试：吃掉「主包稍晚 subscribe」和偶发丢包。  
- **指数退避**（20 tick 起 ×2）：主包长期不在时避免一直高频刷事件。  
- **单次间隔封顶 5 min**：退避不要无限变长，仍保留偶发探活。  
- **累计等待约 5 min 仍无 assign 则停**：判定主包不存在或通道不可用，停止空转；清空 pending 并告警，避免队列静默涨内存。  
- 一旦收到自己的 assign：立即停重试，进入可发送。

**算法**

```
立即 register 一次
elapsed = 0
delay = 20
loop:
  若已收到自己的 assign → 停重试，进入可发送
  等待 delay tick
  elapsed += delay
  若 elapsed >= 6000 → 停止重试，告警，清空 pending 并提示
  register
  delay = min(delay * 2, 6000)
```

间隔例：20 → 40 → 80 → … → 6000（tick；6000 = 5 min）。

### 注销与拼包

- 先发完（或放弃）再 `unregister`，避免短 id 回收后半截分片仍在飞。  
- 主包处理 unregister 时：删除映射，并丢弃该 `senderId` 下未拼完的 group。

### 无 handler 的 topic

收齐后若无 `on(topic)`：打 warn 并丢弃。业务须在副包可能发数据前挂好 handler（或后续再加短时缓冲，首期不做）。

## API

```ts
ChannelReceiver.start();
ChannelReceiver.on('skin', (payload, meta) => { /* ... */ });

const sender = new ChannelSender();
sender.send('skin', longJson);
sender.unregister(); // 可选
```

`meta` 至少含：`senderId`、`uuid`（若表中有）、`groupId`、`topic`。

## 实现注意

- Sender / Protocol 少依赖主包（避免拖 Logger/Config），便于副包复制。  
- 大包可分 tick 发片，降低单 tick 打满。  
- 不校验 `sourceType`（Addon 互信）；若以后要防命令注入再加。
