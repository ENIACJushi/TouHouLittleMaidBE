# 槽位系统手工测试

面向当前已落地能力：`slot:attack_*` 生成与 `Slots.attack`，以及经 `VariantSlot` 接入的历史 `skin:*`（含 `_quit`）。  
`Level` 等业务尚未改组合原子槽，**不要用升级等级代替 attack 槽验收**。

---

## 前置

1. 在 `MaidGenerator` 执行 `npm run build`，确认 `TouHouLittleMaid_BP/entities/maid/maid.json` 已含槽位事件。
2. 编译并同步行为包脚本到测试世界（与日常开发相同流程）。
3. 准备：可驯服女仆、换肤入口、可选假人/敌对生物（测近战伤害时用）。

---

## A. 离线抽查（进游戏前）

在生成后的 `maid.json` 中确认：

| 检查项 | 期望 |
|--------|------|
| 组件组 `slot:attack_12` | `"minecraft:attack": { "damage": 12 }` |
| 事件 `slot:attack_12` | 仅 `add` → `slot:attack_12` |
| 事件 `slot:attack_12_quit` | 仅 `remove` → `slot:attack_12` |
| 区间覆盖 | 存在 `slot:attack_1` … `slot:attack_32` |
| 皮肤卸载 | 存在 `skin:0_quit`（及同结构的其它 `skin:<n>_quit`） |

可选：`TouHouLittleMaid_BP/typescripts` 下执行 `npx tsc --noEmit`，确认脚本无类型错误。

---

## B. 游戏内：Skin / VariantSlot（已接通业务）

**目的**：验证互斥卸载（先 `skin:旧_quit` 再 `skin:新`），换肤仍正常。

### 步骤

1. 召唤并驯服女仆。
2. 连续切换模型编号至少 5 次（含回到曾用过的编号）。
3. 切换皮肤包后再改模型编号 2～3 次。

### 通过标准

- 外形/模型编号与选择一致，无卡死、无报错刷屏。
- 反复切换后仍可正常跟随、工作、再次换肤。

### 失败信号

- 切肤后外形不变或错乱。
- 多次切换后实体行为异常（可疑为旧 `skin:*` 组未卸干净）。

---

## C. 游戏内：Attack 槽（需临时脚本调用）

**目的**：验证 `Slots.attack.set/clear` 与 JSON `slot:attack_*` 成对事件。  
业务层尚未接线，须在测试代码或控制台式调试里**直接调用** `Slots.attack`（例如挂到现有 `thlm:test` 回调，测完可删）。

### 建议用例

站在目标女仆旁，对**同一只**女仆依次操作：

| 序号 | 操作 | 期望 |
|------|------|------|
| 1 | `Slots.attack.set(maid, 12)` | 返回 `true`；`minecraft:attack` 的 damage = 12 |
| 2 | 再 `set(maid, 12)` | 返回 `true`；无异常（同值 no-op） |
| 3 | `set(maid, 16)` | 返回 `true`；damage = 16（隐含先 quit 12） |
| 4 | `set(maid, 0)` 或 `set(maid, 33)` | 返回 `false`；damage 仍为 16 |
| 5 | `Slots.attack.clear(maid)` | 卸下当前 attack 槽组；`Slots.attack.get` 为 `undefined`（DP 已清） |
| 6 | （可选）近战打假人/生物 | 在未 clear、damage=16 时，手感/数值与更高伤害档相符 |

读取伤害示例（在同一调试回调中打日志即可）：

```ts
const atk = maid.getComponent("minecraft:attack");
// 查看 atk?.damage
```

### 注意

- 若同时执行 admin `setm:level:…`，现有 `api:lv_*` 也会写入 `minecraft:attack`，可能覆盖槽位结果；**迁移前请分开测**，不要把「升级」当作 attack 槽通过条件。
- `get` 依赖槽位写入的 DynamicProperty（`slot_attack`）；仅被 `api:lv_*` 改过伤害、从未 `Slots.attack.set` 时，`get` 可为 `undefined`，属预期。
